# Backend (`gtm_studio`)

## Layout (`src/gtm_studio/`)
- `domain/`: pure dataclasses and Pydantic models, the lifecycle state machine, the planner, the fact diff and the safety rule. **No IO**: no SQLAlchemy, FastAPI, anthropic, boto3 or filesystem.
- `services/`: use cases. They take ports (repositories, `LLMClient`, `BlobStore`, `AuditLog`) as constructor arguments and own transactions. The ports live in `services/ports.py`; services never import `gtm_studio.db`, so they receive a `UnitOfWorkFactory` (`Callable[[], UnitOfWork]`) and use `with uow_factory() as uow:`.
- `adapters/`: implementations of the ports: `llm/` (bedrock, mock), `aha/`, `docs/`, `kb/`, `render/`, `tts/`, `storage/`.
- `db/`: SQLAlchemy 2 typed ORM models (`db/models/`, every module imported in `db/models/__init__.py`), repositories (`db/repositories/`) and Alembic migrations (`db/migrations/`). `base.py` (`Base`, `IdMixin`, `TimestampMixin`), `engine.py` (`make_engine`, `make_session_factory`), `uow.py` (`SqlUnitOfWork`, the real `UnitOfWork`), `migrate.py` (Alembic from code), `deps.py` (`get_uow_factory`, and `get_session`, re-exported by `api/deps.py`).
- `auth/`: `AuthProvider` (`providers.py` dev, `oidc.py` OIDC), the dev-user file loader (`dev_users.py`), sessions, the CSRF header middleware, and the `current_actor` / `require(...)` dependencies.
- `audit/`: `SqlAuditLog` (the `AuditLog` port), the request context (`context.py`), the request-ID and access-log middleware (`middleware.py`) and logging set-up (`logging.py`).
- `api/`: FastAPI routers. These are thin: validate, call a service, map to a response schema.
- `worker/`: the job queue consumer.
- `domain/catalog.py`: the catalog's frozen Pydantic models (gates, tiers, asset types, brand) and their lookups: `Catalog.matrix()`, `core_assets()`, `approver_roles_for()`. Pure, so a lookup that fails raises `NotFoundError`. It also has `Issue` (level, catalog-relative `where`, message) and `IssueSummary`.
- `domain/catalog_rules.py`: `validate(catalog, families=..., strict=...)` returns every error and warning at once, ordered by `where` then message. Pure: it never reads a file. Roles are checked here too, so `admin` or `viewer` as an approver role is an error (ADR-0005).
- `catalog/`: the `gtm_catalog/` file IO. `loader.py` (`load_catalog`, `catalog_present`, `loaded_files`, `CatalogLoadError`, which names the file), `frontmatter.py` (YAML header split, rubric criteria), `hashing.py` (`catalog_version_hash`: 12 hex characters over the loaded files, CRLF-insensitive), `families.py` (`KNOWN_FAMILIES`: output families are code, not taxonomy), `todos.py` (`count_todos`: `TODO(confirm)` markers per loaded file) and `source.py` (`check_catalog(root, strict=)`: load, validate and add one warning per file with markers; a file that won't load is one error naming it; `FileCatalogSource`, the `CatalogSource` port over a folder).
- `services/catalog.py`: `CatalogService`, one per process (`app.state.catalog_service`, `api.deps.get_catalog_service`). It holds the loaded catalog as one frozen `LoadedCatalog` (catalog, issues, TODO count, load time), so a reader sees one consistent state.
  - `load_initial()` runs in the lifespan, after the engine: no catalog is the state `missing` (a warning, and every catalog `GET` answers 404 `no catalog loaded`); a present catalog with errors raises `CatalogStartupError` and the app does not start.
  - `reload(actor)` validates **outside** the lock, then commits the `catalog.reloaded` event and the role sync in one unit of work, then swaps the reference under a `threading.Lock`. Errors change nothing and are audited as `catalog.reload_rejected` (the route answers 409 with the same body). It reloads this process only; the worker keeps its catalog until S33.
  - `sync_roles(actor)` makes every role the catalog declares `source=catalog, active=True` (taking over a `dev_seed` or `oidc` row with the same key; its grants take effect at the holders' next request) and deactivates a `catalog` role the catalog dropped (grants stay). System roles are never touched. `catalog.roles_synced` is audited only when something changed. `IdentityRepository.put_role` overwrites; `ensure_role` still leaves an existing role alone (OIDC).
  - `matrix_view()`, `asset_type_view(key)` and `brand_view()` give the routers plain values: the tier x gate matrix is computed by `Catalog` helpers only, never in a router or the frontend.
- `cli.py`: the Typer app `gtm` (`worker`, `db`, `catalog`, `openapi`, `seed`). `gtm catalog show [--path P]` prints a catalog's hash, gates, tiers, tier × gate matrix and triggers. `gtm catalog validate [--path P] [--strict]` prints the issues, then `N errors, M warnings, K TODO(confirm)` and the hash, and exits 1 on any error. `--strict` turns warnings into errors, but `TODO(confirm)` markers stay warnings. `--path` is relative to the working directory.

## Layering (enforced by `uv run lint-imports`)
`cli` > `api` | `worker` > infrastructure > `services` > `domain`. Infrastructure is one layer: `adapters`, `db`, `auth`, `audit` and `catalog` may import each other, so `audit` can use `db` models and `auth` can use `audit.context`. `api` and `worker` must not import each other. `domain` also may not import `gtm_studio.settings`, `yaml` or `alembic`, and `services` may not import fastapi, starlette, sqlalchemy, alembic, yaml, anthropic, boto3, authlib or httpx. (authlib and `httpx2`, its HTTP client, are used only in `auth/oidc.py`.) If a contract blocks legitimate work, stop and say so: don't loosen it silently.

## Conventions
- Python 3.12, fully type-hinted, and `pyright` clean in strict mode for `domain/` and `services/`.
- Settings come only from `gtm_studio.settings.Settings` (pydantic-settings, prefix `GTM_`). Never read `os.environ` elsewhere. Never cache settings with `lru_cache`; pass them in. In handlers, get them with the `api.deps.get_settings` dependency. `Settings.defaults()` ignores the environment (for output that must not vary by machine, such as the OpenAPI export).
- IDs are UUID strings and timestamps are timezone-aware UTC. Every table has `created_at`, and mutable tables have `updated_at`. Use `IdMixin` and `TimestampMixin`: they set the values in Python, and the `UTCDateTime` column type returns aware UTC even on SQLite (which would otherwise return naive datetimes) and refuses naive input. Build timestamps with `domain.clock.utcnow()` (re-exported as `db.base.utcnow`), never `datetime.now()` or `utcnow()` from the standard library. An ORM insert sets `created_at` and `updated_at` from one clock read.
- Columns use portable types only: `String`, `Text`, `JSON`, `DateTime(timezone=True)` (via `UTCDateTime`), `Boolean`, `Integer`. No SQLite-only SQL outside dialect-guarded migration code.
- Every schema change ships an Alembic migration written for SQLite (`render_as_batch=True`) and portable to Postgres. Never use `create_all` outside tests (`tests/service/test_migrations.py` fails if `src/` mentions it).
  - Workflow: change the model, `uv run gtm db upgrade`, then `uv run gtm db revision -m "what changed" --autogenerate`, then **read and edit** the generated file. `tests/service/test_migrations.py` fails when models and migrations disagree.
  - A migration uses `sa.*` types and plain Python only. It never imports application code, because that code changes later and the migration must not.
  - Name constraints through the `Base` naming convention. When a batch migration first touches a table that other tables reference, switch `PRAGMA foreign_keys` off around it in `env.py` (see the S05 notes).
- The engine and session factory are built in the app lifespan (`app.state.session_factory`, `app.state.uow_factory`), never in `create_app`. The lifespan does not migrate: run `gtm db upgrade`. A service dependency takes `Depends(get_uow_factory)` (`db/deps.py`) and never reads `app.state` itself. Routers never query the database: reads go through a service method too, and `Depends(get_session)` is only for `/api/health` and diagnostics (ADR-0006). A state change goes through a `UnitOfWork`, so the change and its audit event commit together.
- File loaders (YAML, Markdown frontmatter) live in infrastructure (`catalog/`, `auth/`, `adapters/`). Services take parsed values, never paths (ADR-0006).
- API schemas live in `api/schemas/`, separate from ORM models. Every endpoint has a `response_model` and a permission dependency.
- **Identity** (ADR-0002):
  - A handler gets the caller from `auth.deps`: `current_actor` (any signed-in user, 401 otherwise) or `require(Permission.X, ...)` (403 when missing). The only open routes are `/api/health`, `/api/auth/options` and the three that start a session: `/api/auth/dev/login`, `/api/auth/oidc/login` and `/api/auth/oidc/callback`. `tests/api/test_auth.py` lists every route and fails when another one lacks `current_actor`, so add the dependency, don't extend the allowlist.
  - Permissions and "may this actor approve this gate" are pure code in `domain/identity.py`. `admin` has every permission but `can_approve(actor, gate_roles)` is true only for a holder of one of the gate's approver roles (separation of duties). Any role that isn't `admin` or `viewer` is an approver role.
  - Services get repositories from the unit of work (`uow.identity`; the ports are in `services/ports.py`, the SQLAlchemy versions in `db/repositories/`). Repositories flush and never commit. They return domain values, never ORM objects.
  - The session is Starlette's signed cookie (`gtm_session`, httpOnly, `SameSite=Lax`, `Secure` in production, 8 h). `auth/csrf.py` rejects `POST`/`PUT`/`PATCH`/`DELETE` under `/api` without `X-Requested-With: gtm-studio`. Every new state-changing endpoint also writes an audit event (next bullet).
  - Settings refuse `GTM_ENV=production` with the dev provider or the built-in `session_secret`. Dev users come from `config/dev_users.yaml` through `gtm seed dev-users` (audited, no actor: `user.seeded`, `user.updated`, `user.roles_set`). Dev login with an ID that names nobody is logged (`dev sign-in denied`), not audited; an inactive user's attempt is audited.
  - **OIDC** (`auth/oidc.py`, ADR-0002; setup in `docs/hosting.md`):
    - `GTM_AUTH_PROVIDER=oidc` needs `GTM_OIDC_ISSUER`, `_CLIENT_ID`, `_CLIENT_SECRET` and `_REDIRECT_URL` (Settings names the missing ones), and in production they and `GTM_FRONTEND_BASE_URL` must be https. The lifespan builds `app.state.oidc_provider` (None otherwise: the two routes answer 404) and reads `config/oidc_roles.yaml` then, so a bad file stops start-up. Tests build the settings with the `oidc_settings` fixture and production environments with `hosted_env`.
    - authlib does the protocol work (state, nonce and the PKCE verifier live in the session cookie; signature, `iss`, `aud`, `exp` and the nonce are checked). The provider adds policy: people are identified by `(oidc, sub)`, **never matched by email** (an email owned by another user is a denial), and a deactivated user is refused before any role change.
    - Role sync (`IdentityService.sync_roles`) replaces only the grants whose `source` is `oidc`; grants from other sources stay. A role key that no row exists for is created **inactive** and logged, so a typo or an early mapping grants nothing (`CatalogService.sync_roles` activates it when the catalog declares it).
    - A callback failure before the IdP vouched for anyone (`OidcFlowError`) is logged and redirects to `/login?error=failed`; it is **not audited**, because the endpoint is open and audit rows can't be deleted. Once the IdP has vouched for someone, a refusal (`OidcDeniedError`) is audited as `auth.login_denied` with a `reason` and redirects to `/login?error=denied`.
    - `next` is kept in the session at login and checked by `safe_next` twice (same-site paths only; the frontend's `safeNext` is aligned with it in S15b). Tests fake the IdP with a real signed ID token (`FakeIdp` in `tests/api/test_oidc.py`), replacing only the two authlib methods that touch the network.
- **Audit** (ADR-0002, invariant 3):
  - A service records an event inside the unit of work that makes the change: `uow.audit.record(actor, AuditAction.X, entity_type, entity_id, details=..., before=..., after=...)`. It adds to the open transaction and never commits, so the event and the change commit or roll back together (`tests/service/test_audit.py` proves both directions). Never open a second unit of work for the event.
  - Add each new action to `AuditAction` in `domain/audit.py` (`<area>.<verb>`; the stored value is the plain string, so never change one). `actor=None` means no signed-in person (a background job, or a failed sign-in) and stores `actor_display="system"`.
  - `before` / `after` are plain JSON values and are stored only as `canonical_hash`es. `details` is stored as is and is shown to anyone with `audit:read`: no document text, prompts or secrets in it.
  - The request fields (request ID, IP, user agent) come from `audit.context` by themselves. `current_actor` binds the actor to the request for the access log.
  - `audit_events` is append-only: the migration adds SQLite triggers that reject UPDATE and DELETE (Postgres uses `REVOKE`, S09's `docs/hosting.md`). The table has `occurred_at` instead of `created_at` and no `updated_at`. Never write a migration that alters rows in it.
  - `SqlAuditLog` stamps each event strictly later than the last one in the process: the Windows clock ticks every 1 to 15 ms, and events in one transaction would otherwise tie and sort by random ID.
  - Read it through `ActivityService` (`GET /api/activity` needs `audit:read`; `GET /api/activity/me` is any signed-in user's own events). Pagination is keyset on `(occurred_at, id)` behind an opaque cursor.
- Every router sets `tags`: operation IDs are `<tag>_<function name>`, and they end up in the generated TypeScript client.
- **The OpenAPI schema never depends on settings.** Mount every route unconditionally and decide inside the handler (a disabled feature answers 404). `gtm openapi` builds the app from `Settings.defaults()`, and the contract test compares its output to `frontend/openapi.json`. Use `gtm_studio.api.openapi.render_openapi` for any serialization.
- Everything is under `/api`, including the interactive docs (`/api/docs`, off when `GTM_ENV=production`).
- CORS is off by default: the Vite proxy makes the browser see one origin. `GTM_CORS_ORIGINS` (comma-separated, explicit origins, no `*`) adds the middleware. Middleware adds no routes, so it is the one thing that may depend on settings without breaking the OpenAPI rule above.
- Add or change an endpoint → regenerate `frontend/openapi.json` and `frontend/src/api/schema.d.ts` in the same change (`tests/api/test_openapi_contract.py` fails otherwise, and says how).
- To list or audit routes, use `gtm_studio.api.introspection.list_routes` (or the `api_routes` fixture). FastAPI 0.165 keeps `include_router` results as lazy wrappers, so `app.routes` is not flat and its `path` values lack the prefix.
- Never call `create_app` with side effects: DB, catalog and other IO belong in the lifespan, so `create_app` stays cheap and `app.openapi()` works without them.
- stdout belongs to command output (`gtm openapi > file`). Logs go to stderr.
- Errors: raise domain exceptions in services, never `try/except → HTTPException` in a router. Subclass `NotFoundError`, `ConflictError`, `InvalidInputError` or `NotPermittedError` (`domain/errors.py`); `api/errors.py` maps them to 404/409/422/403 with `{"detail": exc.detail}` (ADR-0006). The client sees `detail`: no request data, personal data or secrets in it.
- Logging: `structlog.get_logger()`. Never `print`. Never log prompt bodies, document text or secrets at info level.
  - `audit.logging.configure_logging(settings)` sets it up once per process: JSON lines unless `env=dev` (console), everything on stderr, stdlib logging (uvicorn, alembic) through the same renderer. The `gtm` Typer callback and the app lifespan call it, not `create_app` (building the app stays silent), and it does nothing when structlog is already configured (so a test's `capture_logs()` is safe).
  - `RequestContextMiddleware` is the outermost middleware: every response carries `X-Request-ID` (an inbound one is kept only if it matches `[A-Za-z0-9-]{8,64}`), and one `request` line is logged with `method`, `path` (no query string), `status`, `duration_ms` and `actor_id`. It never reads a body. uvicorn's own access log is silenced because it prints the query string.
  - `audit.logging.QUIET_LIBRARIES` (httpx, anthropic, boto3, SQLAlchemy engine, ...) are held at WARNING whatever `GTM_LOG_LEVEL` is, because at INFO or DEBUG they log URLs, SQL parameters or message bodies. Add a client library there when you add one.
  - uvicorn prints "Started server process" and "Waiting for application startup" before the lifespan runs, so those two lines stay plain text.

## Tests (`tests/`)
- `tests/unit/` covers domain code, with no DB.
- `tests/service/` runs against a temp SQLite DB migrated with Alembic: fixtures `migrated_engine` (a fresh database per test at head: a file copy of `_migrated_template`, which Alembic migrates once per run) and `db_session` (a session on it). Tests of Alembic itself (`test_migrations.py`) override `migrated_engine` to run the migrations. The `client` fixture depends on `migrated_engine`, so API tests get the schema too.
- `tests/api/` uses FastAPI `TestClient` with the `login_as(role_key)` fixture: it seeds the dev users (`seeded`), signs in as the first one holding that role and sends the CSRF header (`csrf=False` leaves it off). Each call gets its own cookie jar. The `app` fixture is the app it uses, so a test can add a probe route before calling it. `uow_factory` gives a service the migrated test database.
- **Starting the app now touches the database** (the catalog's role sync): with a catalog present, an unmigrated database stops start-up with `no such table: roles` (run `gtm db upgrade`), and `/api/health` can no longer report `db: error` in that case. So a test that starts the app needs `migrated_engine`, or `no_catalog_settings` (an empty folder: the app starts without a catalog and writes nothing). The `settings` fixture sets `catalog_dir` to `catalog_min`, so tests never read the real `gtm_catalog/`; its start-up writes a `catalog.roles_synced` event, so a test that counts audit events must allow for it. `Me` has `role_info` (key, label from the roles table, `kind` from `role_kind`).
- Fixtures: `tests/fixtures/` holds a minimal catalog (`catalog_min/`, neutral names, and clean even under `--strict`) and sample Aha! files. Use the `catalog_min_dir` (its path), `catalog_min` (loaded) and `catalog_min_copy` (a writable copy in `tmp_path`, for tests that break it) fixtures. To test a validator rule, break the loaded `catalog_min` in memory with `model_copy(update=...)` (see `tests/unit/test_catalog_rules.py`). The demo catalog (`fixtures/demo/catalog/`, 11 asset types converted from the old POC) is what S15, S15b and e2e run on; `tests/service/test_demo_catalog.py` keeps it valid.
- Markers: `bedrock` (real AWS calls, deselected by default) and `slow`.
- pytest runs in `importlib` import mode: test folders have no `__init__.py`, and tests can't import from `conftest.py` or from each other. Share code through fixtures, or put it in `src/`.
- An autouse fixture removes `GTM_*` variables and disables the `.env` file, so tests never see the developer's machine. Build settings with `Settings(env="test", ...)` (the `settings` fixture). Don't pass `_env_file=`: pyright rejects it. To test `.env` loading, `monkeypatch.setitem(Settings.model_config, "env_file", path)`.
- A test client needs `with TestClient(app)` (the `client` fixture does this) so the lifespan runs.
- Logging in tests: an autouse fixture puts structlog and the stdlib loggers back after every test, because the app and the CLI configure them process-wide. To assert on log lines, use the `stderr_logs()` fixture (JSON lines written to stderr since the last call); `structlog.testing.capture_logs()` still works for single events but doesn't see bound request context.
- Never assert that two separate clock reads are equal or ordered: the Windows clock ticks every 1 to 15 ms. To test timing, patch the clock (`test_db_base.py` does).
- When porting from the old POC, port its test cases first. They are the behavioural spec.
