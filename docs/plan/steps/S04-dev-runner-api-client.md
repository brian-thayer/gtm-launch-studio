# S04: Dev runner, Vite proxy, OpenAPI → TypeScript client loop

Status: done
Milestone: M1
Depends on: S02, S03
Human in the loop: no
Size budget: about 300 lines

## Goal
One command starts the API, the worker placeholder and the frontend. The frontend calls the backend only through a client generated from OpenAPI, and a test fails if the committed schema drifts from the backend.

## Why it matters
It locks in the contract-first loop that keeps Sonnet from hand-writing mismatched API types in every later step.

## Read first
- `frontend/CLAUDE.md` (API client rules)
- `backend/src/gtm_studio/api/app.py`, `backend/src/gtm_studio/cli.py`
- `frontend/vite.config.ts`, `frontend/playwright.config.ts`

## Create / modify
- `frontend/vite.config.ts`: `server.proxy` sends `/api` to `http://127.0.0.1:8000`, so the session cookie is same-origin.
- `frontend/openapi.json`: generated by `uv run gtm openapi > ../frontend/openapi.json`, run from `backend/`.
- `frontend/src/api/schema.d.ts`: generated by `npm run gen:api` and committed.
- `frontend/src/api/client.ts`:
  - `export const api = createClient<paths>({ baseUrl: "" })`;
  - a middleware that adds `X-Requested-With: gtm-studio` to every request (the CSRF header S06 requires) and sends credentials;
  - typed error helpers.
- `frontend/src/hooks/useHealth.ts`: TanStack Query hook for `GET /api/health`.
- `frontend/src/pages/HomePage.tsx`: shows an "API: ok / unreachable" badge.
- `backend/src/gtm_studio/api/app.py`: optional CORS middleware, only when `GTM_CORS_ORIGINS` is set (comma-separated). It is off by default because the proxy is the norm. Add `cors_origins: list[str] = []` to Settings. Middleware doesn't change the OpenAPI schema, so this respects the "schema never depends on settings" rule (see `backend/CLAUDE.md`).
- Since S02 the interactive docs are at `/api/docs` and `/api/openapi.json` (off in production), so the Vite `/api` proxy already covers them.
- `backend/tests/api/test_openapi_contract.py`: asserts that `render_openapi(create_app(Settings.defaults()))` (from `gtm_studio.api.openapi`, the same function `gtm openapi` uses; S02) equals `Path("../frontend/openapi.json").read_text()`. `read_text` normalizes CRLF, which matters if git's autocrlf rewrites the file on checkout. On failure the message says: "Run `uv run gtm openapi > ../frontend/openapi.json` then `npm run gen:api`."
- `.gitattributes` at the repo root: `*.json text eol=lf` and `*.d.ts text eol=lf`, so the generated files are byte-stable on Windows.
- `scripts/dev.ps1`:
  - `-Stop` switch: kills whatever listens on ports 8000 and 5173, via `Get-NetTCPConnection` and `Stop-Process` on the owning process tree.
  - By default it:
    1. warns if those ports are in use;
    2. runs `uv run gtm db upgrade` if that command exists (from S05; skip quietly before then);
    3. starts uvicorn (`--factory --reload --port 8000`), `gtm worker` and `npm run dev`, each in its own window titled `gtm-api`, `gtm-worker` and `gtm-web`;
    4. prints the URLs.
- `frontend/playwright.config.ts`: `webServer` becomes an array that starts the backend (uvicorn on 8000, `cwd: ../backend`, env `GTM_ENV=test`) and Vite.
- `frontend/e2e/smoke.spec.ts`: also asserts "API: ok".
- Root `README.md` and root `CLAUDE.md`: confirm the dev commands.

## Notes
- **Drift check done.** I appended a throwaway `GET /api/health/drift-probe` route to `health.py` without regenerating. `test_openapi_contract.py` failed with the "Run `uv run gtm openapi ...` then `npm run gen:api`" message. I reverted the route and the test passed again.
- **Contract test path.** It reads `REPO_ROOT / "frontend" / "openapi.json"` (from `Settings`) instead of the card's cwd-relative `../frontend/openapi.json`, so it passes from any working directory.
- **`dev.ps1` refuses to start when 8000 or 5173 is busy** (the card says "warns"). Starting anyway would open windows that die at once (Vite has `strictPort`). It names the owning process and says to run `-Stop`. The worker has no port, so `-Stop` also needs `storage/dev-pids.json` (window PIDs plus start times, to survive PID reuse). The script also finds `uv` under `%APPDATA%\Python\Python3*\Scripts` when it isn't on PATH, and waits until `http://localhost:5173/api/health` answers (which proves the proxy) before printing the URLs.
- **Playwright starts the API from `backend/.venv`** (`python -m uvicorn ...`), not `uv run`, so `npm run e2e` works when `uv` isn't on PATH. It needs a one-time `uv sync`. Both servers are reused if already running (except under `CI`).
- **`GTM_CORS_ORIGINS`** is parsed as a comma-separated list (`NoDecode`, otherwise pydantic-settings wants JSON) and rejects `*`, because the CORS middleware allows credentials. Unverified: `$Host.UI.RawUI.WindowTitle` sets the `gtm-*` window titles, but under Windows Terminal I couldn't read them back (`MainWindowTitle` is empty because the terminal owns the window).
- **Bug found and fixed while testing `-Stop`:** Windows PowerShell 5.1's `ConvertFrom-Json` returns a JSON array as one object, so the pid-file path failed and only the port sweep ran (the worker, which has no port, survived). The script now pipes the result through `ForEach-Object` to unroll it. After the fix, start, a second start (refused), and `-Stop` all behave, and ports 8000 and 5173 are free afterwards.
- Reviewer (`code-reviewer`): PASS WITH NITS, nothing blocking. It could not run `dev.ps1` itself (it opens windows); I ran the full start/stop cycle. The `git status` noise on about 16 untouched frontend files is autocrlf stat churn after `prettier --write` (`git diff HEAD --stat` shows only the intended files).
